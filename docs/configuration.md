## 設定參數

全部在 `watcher.js` 最上方的 `CONFIG`。**一般人只要改 `month` 和 `days` 兩個。**

| 參數 | 預設 | 說明 |
|---|---|---|
| `month` | `10` | **要監看幾月**（1~12）。程式會自動切換到該月，不用自己算按幾次 Next。 |
| `year` | `null` | 年份。`null` = 自動（沿用頁面顯示的年份；目標月份比目前顯示的早，就當作明年）。 |
| `days` | `'10-13'` | **要監看哪幾號**。可寫 `'10-13'`、`'10,12,15-17'`、`'25'` 或 `[10,11]`。建議一次不超過 7 天。 |
| `interval.start` | `60000` | 起始「每輪結束後的休息時間」（毫秒）。 |
| `interval.step` | `10000` | 每次成功縮短／失敗退回的幅度。 |
| `interval.floor` | `30000` | 休息時間下限（毫秒）。**越小越容易被限流**（舊預設 10000 約 20～30 分鐘就被擋）。⚠ 預設的輪流模式（`rotate.enabled: true`）**不使用休息時間**，這個值只用在失敗退避；只有 `rotate.enabled: false`（每輪連查全部日期）時才是兩輪之間的休息。 |
| `interval.max` | `180000` | 失敗退避時的上限。 |
| `interval.probeAfterOk` | `10` | 因失敗被鎖住的下限，需在該下限連續成功幾次才放寬一級。 |
| `initialDelay` | `0` | 啟動後先等多久再開始第一輪。剛被限流時可設 `240000`（4 分鐘）。 |
| `reloadEvery` | `180` | 每幾輪才整頁重新載入一次（預設約 4 小時：一輪 ＝ 每個日期各查一次，4 天 × 20 秒 ＝ 80 秒）。設 `1` = 每輪都重載（請求量約多一倍，較容易被限流）。一次重載約 61 個請求；2026-09-29 有一次被擋剛好發生在重載後的第一個查詢（之後又有一次不是），所以預設放得很寬。頁面出問題時仍會立刻重載。 |
| `blockedWaitMs` | `1500000` | 第一次被限流（429）後先暫停多久再送第一個試探（25 分鐘；依實測封鎖約 26～29 分鐘）。見「限流」一節。 |
| `blockedRetryMs` | `120000` | 第一個試探仍被擋時，之後每隔多久再試 1 個請求（2 分鐘）。 |
| `budget.windowMs` / `budget.maxCalls` | `30 分鐘` / `100` | 查詢預算（安全上限）：視窗內最多送幾個時段查詢（約每分鐘 3 個）。`maxCalls: null` = 不限制（不建議）。被擋時會自動調降。**改 `rotate.everyMs` 想更快時，這個也要一起調高**，否則實際速度會被它壓住（見下方對照表）。沒有任何速率被證明安全，見[限流](rate-limit.md)。 |
| `budget.learnFactor` / `budget.min` | `0.7` / `30` | 被擋時，新預算 = 窗口內查詢量 × 0.7（不低於 30）。 |
| `rotate.enabled` / `rotate.everyMs` / `rotate.jitterMs` | `true` / `20000` / `2000` | **輪流模式（溫和模式）**：每次只查 1 天、日期輪流查，而不是每輪連查全部日期。每隔 `everyMs` 查 1 天（預設 20 秒 ＝ 每分鐘 3 個），`jitterMs` 是隨機抖動（±）。實際間隔取 `everyMs` 與預算平均分散較大者。開啟時 `interval.*` 只在失敗退避時使用；`enabled: false` 回到每輪連查全部日期。**越快越容易被限流**（每 10 秒 1 個 ＝ 每分鐘 6 個，約等於曾被擋的速率）。 |
| `budget.pace` | `true` | 預算「平均分散」：兩輪**開始**之間至少相隔 `視窗 × 每輪查詢數 ÷ 預算`（`rotate.enabled: false` 時：30 分鐘 × 4 天 ÷ 預算 100 ＝ 72 秒）。它比自適應休息長時，以它為準。設 `false` 則只受休息時間與預算上限控制（會先猛送、再被預算擋到長時間停擺，較容易被限流）。 |
| `timing.startupWaitMs` | `30000` | 腳本啟動時，最多等多久讓日曆出現。用 Tampermonkey／AdGuard 這類使用者腳本時，腳本常比網頁自己畫日曆的程式更早執行，所以要耐心等；逾時才判定「不是訂票頁」。網路很慢可調大。 |
| `timing.readyTimeoutMs` | `20000` | 等頁面載入並出現日曆的上限。網路慢就調大。 |
| `timing.ajaxTimeoutMs` | `12000` | 點日期後，等該次查詢回應的上限。 |
| `timing.jitter` | `400~1200` | 每天之間的隨機間隔，避免規律到像機器。 |
| `notify.*` | 全開 | 提醒方式，見下方「提醒設定」。 |
| `panel.fontPx` / `panel.widthPx` | `40` / `820` | 面板字體大小與寬度。 |
| `resume.*` | 開 | 中斷後自動接續（見下節）。 |
| `keepAwake` | `true` | 自動要求瀏覽器保持螢幕喚醒（不能阻止電腦關機／合蓋睡眠）。 |
| `workerTimers` | `true` | 用 Web Worker 計時，降低分頁在背景被 Chrome 節流的影響；失敗會自動退回一般計時。 |
| `allowMultipleTabs` | `false` | 是否允許多個分頁同時監控（不建議）。 |
| `maxHistory` | `200` | 歷史紀錄存檔（`localStorage`）最多保留幾筆；面板只顯示最近 6 筆；記憶體中超過兩倍（400 筆）會修剪回這個數字。完全關閉 Chrome 後網站資料可能被清掉（作者環境實測會），要長期留存請用 `__ticketWatcher.exportHistory()` 匯出 CSV。 |

**查詢速度對照表**（要同時改兩個數字；只改 `everyMs` 會被預算壓回去，面板會說明）：

| 想要 | `rotate.everyMs` | `budget.maxCalls` |
|---|---|---|
| 每 30 秒查 1 天（每分鐘 2 個，最保守） | `30_000` | `60` |
| **每 20 秒查 1 天（預設，每分鐘 3 個）** | `20_000` | `100` |
| 每 10 秒查 1 天（每分鐘 6 個，實測約半小時就被擋一次） | `10_000` | `200` |

**不想改檔案？** 貼程式「之前」先在 Console 執行下面這行，就能覆寫任何設定。例如改成每 10 秒查 1 天
（每天約 40 秒查一次；**越快越容易被限流**，被擋時程式會自動暫停並把預算調降）：

```js
window.ticketWatcherConfig = { rotate: { everyMs: 10000 }, budget: { maxCalls: 200 }, reloadEvery: 360 };
```

`budget.maxCalls` 也要跟著調高（30 分鐘 200 個 ≈ 每 9 秒 1 個），否則預算會把速度壓住；
`reloadEvery: 360` 是為了讓重載維持在約 4 小時一次（360 輪 × 4 天 × 10 秒）。

**已經在跑的監控，想臨時改速度**（重新整理頁面就會回到預設）：在該分頁的 Console 貼

```js
__ticketWatcher.config.rotate.everyMs = 30000;
__ticketWatcher.config.budget.maxCalls = 60;
__ticketWatcher.state.budget = 60;
```

## 提醒設定（桌面版 Chrome：macOS／Windows）

有「新出現」的票時，會同時觸發下列提醒（都可以在 `CONFIG.notify` 個別關掉）：

| 提醒 | 說明 |
|---|---|
| 🖥 系統通知 | 出現在 macOS 通知中心／Windows 動作中心，會一直停留到你點掉（`requireInteraction`）。點通知會直接帶你回到此分頁。 |
| 🔔 提示音 | 用 Web Audio 合成，不需要任何音檔。你沒在看螢幕時，每 6 秒再響一次，最多持續 3 分鐘。 |
| 🗣 語音 | 溫柔女聲念「有票囉，請盡快前往訂票」。預設自動挑台灣國語女聲（macOS：Meijia → Sandy → Shelley → Flo；Windows：HanHan／Yating；備援 Google 國語（臺灣））。可用 `notify.voice.name` 指定，`rate`／`pitch` 調語速與音調。 |
| ✨ 標題閃爍 | 分頁標題在 `🎫有票! …` 與 `🔔🔔 有票了！ …` 之間交替，切在別的分頁也看得到。 |
| 🔴 分頁圖示紅點 | 分頁的小圖示變成紅點驚嘆號。 |
| 🟥 面板變紅 | 只要仍有票，面板就保持紅色，並列出所有日期／時段／剩餘數。 |

**你看到了就會自動停止吵人**：點一下頁面、按任何鍵、或切回此分頁，聲音與閃爍就會停止（面板仍會保持紅色）。

### 第一次使用，請做這兩件事（各只要一次）

1. **在頁面上任意點一下。** Chrome 規定網頁必須先被使用者操作過才能出聲。面板最後一行會顯示 `🔊 提示音與語音：🔇 尚未啟用（請在頁面上點一下）`，點過之後變成 `✅ 已啟用`。
2. **允許通知。** 面板倒數第二行顯示 `🔔 桌面通知：✅ 已開啟` 才代表可用；若是 `❌ 被封鎖`（或 `❓ 尚未允許`）：
   - Chrome：網址列左側的 🔒 → **網站設定** → **通知** → 改成**允許**。
   - **macOS**：系統設定 → 通知 → Google Chrome → 允許通知；並**關閉「專注模式」／勿擾**。
   - **Windows**：設定 → 系統 → 通知，開啟通知；並**關閉「專注助理」**。

### 先測試再開始

在 Console 執行 `window.__ticketWatcher.testAlert()`，會模擬一次「有票」：你應該會看到通知、聽到提示音與語音、看到標題閃爍與紅點。點一下頁面即可停止。**建議每次開始長時間監控前先測一次。**

> 語音的可用聲音因電腦而異。查看清單：`speechSynthesis.getVoices().map(v => v.name + ' | ' + v.lang)`。
> 本工具只使用系統／瀏覽器內建的合成語音，不提供也不模仿特定真人的聲音。

## 畫面說明

右上角面板（字體大、不會擋住操作）：

```
🎫 有票監控 10/10–10/13
輪流查詢: 每 20 秒查 1 天（4 天輪流，每天約 80 秒查一次）
                                ← 預設的「輪流模式」：一次只查 1 天，四天輪流
狀態: 讀取 10/12…               ← 目前在做什麼
次數: 22  連續成功: 3  失敗: 0    ← 已成功查詢幾次
下一次查詢: 21 秒                ← 倒數
上次: 9/29 12:21:46 10/12 20筆（4天輪流）, 全售罄
📊 查詢預算 88/100（近 30 分鐘）    ← 最近 30 分鐘已送幾個時段查詢／上限
【目前有票】                     ← 有票時才會出現，且整個面板變紅
10/11 5班10:30-11:00(剩3)
【歷史紀錄】                     ← 最近 6 筆「新出現」的票
9/29 14:05:12 → 10/11 5班10:30-11:00 剩3
```

分頁標題在有票時會變成：

```
🎫有票! 10/11 5班10:30-11:00、6班11:00-11:30 | 10/12 20班18:00-18:30
```
