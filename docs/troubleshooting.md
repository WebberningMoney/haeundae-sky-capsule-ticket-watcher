## End-user 注意事項

> 請務必讀完。

1. **請保持分頁開啟、電腦不睡眠。** 關掉分頁、關機、合上螢幕睡眠，監控都會停止。
2. **有票後請自己盡快到網站下單。** 本工具不會幫你訂票，票也可能在你看到通知的當下已被搶走。
3. **請勿把頻率調到極限。** 頻繁請求可能造成：被限流（429）、被暫時封鎖 IP，甚至影響你正常訂票。
4. **不要繞過網站的防護。** 本專案刻意不偽造 `X-Schedule-Token`；請勿改成繞過防機器人驗證的版本。
5. **遵守網站服務條款與當地法規。** 僅限**個人自用監看**；請勿用於黃牛、轉售、大量搶票或影響他人購票。
6. **隱私**：腳本只在你的瀏覽器執行，不會把任何資料傳到第三方。歷史紀錄僅存在你的 `localStorage`。
7. **從不明來源貼到 Console、或安裝成使用者腳本的程式碼都有風險**：請先自行閱讀 `watcher.js`（有完整註解），確認無誤再貼上或安裝。
   使用者腳本會在符合網址的每一次頁面載入時自動執行，所以 `@match` 請保持盡量窄；本專案的 `.user.js` 已關閉自動更新。
8. **網站改版會失效**：若網站改了按鈕文字（`Next`）、時段文字格式（`입장`／`剩余`）或流程，需要對應修改。
9. **語系**：目前依賴中文版頁面的文字（`Next`、`剩余`）。其他語系頁面需調整選擇邏輯。
10. **通知限制**：預設僅標題＋面板；分頁在背景時，請留意分頁標題變化，或開啟 `desktopNotification`。

## 常見問題與疑難排解

| 現象 | 可能原因 | 處理 |
|---|---|---|
| 面板顯示「失敗: … 無資料（可能被限流）」 | 被限流（429／`요청실패`） | 腳本會自動暫停並退避；封鎖約 26～29 分鐘會自己解除。建議降低查詢速度（`rotate.everyMs` 調大）、縮小 `days`。 |
| 一直讀不到時段 | 月份／日期設錯、該月份尚未開放預訂、網路慢 | 確認 `month`／`days`；把 `waitAfterDayClick` 調大到 4000～5000。 |
| 面板顯示「被網站限流(429)，暫停到 HH:MM」 | 請求太密，網站限流 | 什麼都不用做，程式會在時間到後自動只送 1 個請求試探並恢復。可考慮調高 `interval.floor`。 |
| 面板顯示 `🔔 桌面通知：❌ 被封鎖` | Chrome 或系統封鎖了通知 | 見「提醒設定」的兩個步驟。改完設定後約 5 秒內面板會自動更新，不必重新整理。 |
| 明明允許了通知，面板仍顯示被封鎖（舊版問題） | 舊版用 `Notification.permission` 判斷，這個值在部分環境會一直回報 `denied`，即使實際是允許的 | v2 已改用 `navigator.permissions.query` 為準，並實測過真的能送出通知。若你仍看不到系統通知，請檢查 macOS「系統設定 → 通知 → Google Chrome」與「專注模式」。 |
| 面板顯示 `🔊 提示音與語音：🔇 尚未啟用` | Chrome 規定要先有人操作過頁面才能出聲 | 在頁面任意處點一下。 |
| 沒聽到語音 | 網路語音需要連網；或系統沒有該聲音 | 斷網時會自動改用本機女聲；也可在 `notify.voice.name` 指定其他聲音。 |
| 面板顯示「⚠️ 無法啟動：另一個分頁已經在監控」 | 已有另一個分頁在跑 | 關掉另一個，或（不建議）把 `allowMultipleTabs` 設為 `true`。 |
| 面板顯示「面板變紅、提示 ⚠️ 已停止」 | 連續 3 次找不到日曆元素（網站可能改版） | 確認頁面是訂票頁；若網站改版，需要更新腳本。 |
| 用使用者腳本（Tampermonkey／AdGuard）啟動，面板顯示「無法啟動：這個頁面找不到日曆」 | 腳本比網頁早執行，日曆還沒被畫出來（訂票頁的日曆是網頁自己的程式事後產生的，原始 HTML 裡沒有）。**2.1.0 以前的版本會直接誤報** | 更新到 2.1.1 以上（重新安裝最新的 `.user.js`，不會自動更新）：新版會先等日曆出現，最多 30 秒。網路很慢可調大 `timing.startupWaitMs`。 |
| 面板顯示「⚠️ 無法啟動」 | 啟動前檢查沒通過（貼錯頁面、日期寫錯…） | 照面板上的中文提示修正後重貼。點一下面板可關閉。 |
| 面板下方出現「⚠ 分頁在背景」 | 此分頁被切到背景／被遮住，瀏覽器讓它變慢 | 把此分頁拉到前景，或拖出成獨立視窗。 |
| 顯示「切不到 X 月」 | 該月份還沒開放預訂，日曆按不到那個月 | 改成已開放的月份，或等開放後再跑。 |
| 面板沒出現 | 貼到錯誤的分頁／Console 選到 iframe 環境 | 確認在訂票頁的**最上層**（Console 左上角 context 選 `top`）。 |
| 貼上被拒 | Chrome 防貼上保護 | 先在 Console 輸入 `allow pasting`，再貼。 |
| 重新整理後監控消失 | 腳本存在頁面記憶體中 | 重新貼上（歷史紀錄會保留）。用 [Tampermonkey](../README.md#方式-b自動啟動tampermonkeyviolentmonkey-或-adguard) 可自動執行。 |
| 裝了 Tampermonkey，打開訂票頁卻沒有面板 | 沒開「允許使用者指令碼」；腳本被關閉；`@match` 網址不符 | 依[自動啟動](../README.md#方式-b自動啟動tampermonkeyviolentmonkey-或-adguard)的「驗證」步驟逐項檢查。 |
| 雙擊 `restart-chrome.command` 出現「could not be executed because you do not have appropriate access privileges」 | 單獨下載或下載 ZIP 會遺失檔案的「可執行」權限 | 終端機執行 `chmod +x <檔案路徑>` 後再雙擊；或改用 `bash <檔案路徑>` 執行。 |
| 重開 Chrome 後歷史紀錄不見了 | Chrome 設定為關閉時清除網站資料 | 預期行為；重開前先 `__ticketWatcher.exportHistory()` 匯出 CSV。 |
| 出現 `403` | 有人嘗試直接呼叫 API（缺少 `X-Schedule-Token`） | 不要直接呼叫 API；使用本腳本的 UI 流程。 |
| 標題沒變、面板沒紅，但你在別處看到有票 | 該時段在兩輪之間才釋出／又被搶走 | 縮短休息時間（注意限流風險）。 |

## 已知限制

- 只能在**開著的分頁**中運作，不是背景服務；無法在電腦關機時通知你。瀏覽器也不允許網頁阻止電腦「關機／合蓋睡眠」，`keepAwake` 只能降低閒置睡眠的機率。
- 分頁若長時間在**背景**，Chrome 會限制計時器頻率，導致整體變慢；請保持前景或獨立視窗。
- 每輪都要重新載入頁面並逐日點擊，**耗時與天數成正比**（約每天 3～5 秒）。
- 依賴頁面 DOM 文字格式，網站改版就可能失效。
- 限流門檻不公開，**目前也沒有任何速率被證明安全**：實測 129 個/30 分鐘被擋、87 個/30 分鐘也被擋過（在重載頁面後），另一段 88 個/30 分鐘則連續跑了 2 小時。預設值是「目前最保守的猜測」，被擋時程式會暫停約 26 分鐘後自動再試，這段時間看不到票。
- 無法保證訂票成功；有票到下單之間仍有競爭。

## 除錯與內部狀態

Console 可用：

```js
window.__ticketWatcher.state      // 完整內部狀態（目前間隔、失敗次數、有票結果…）
window.__ticketWatcher.config     // 目前設定
window.__ticketWatcher.log()      // 完整事件記錄（帶時間）
window.__ticketWatcher.history()  // 有票歷史（何時、哪天、哪個時段、剩幾張）
window.__ticketWatcher.stop()     // 停止並移除面板
window.__ticketWatcher.testAlert()      // 模擬一次「有票」，測試通知／聲音／語音
window.__ticketWatcher.exportHistory()  // 下載有票歷史（CSV）
window.__ticketWatcher.exportLog()      // 下載完整事件記錄（純文字）
window.__ticketWatcher.state.blocks     // 過去每波限流持續多久
```

事件記錄範例：

```
12:29:07 結果: 9/29 11:27:44 22天/440筆, 4天有票!
12:29:07 ★新增有票 10/17 13班14:30-15:00 剩1
12:29:07 休息縮短→70s
12:32:48 失敗: 模擬失敗(測試)
12:33:01 退回上一級→90s
```
